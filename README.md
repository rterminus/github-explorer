# GitExplorer

A GitHub profile explorer designed for developers. Search for any GitHub user to view profile statistics, public information, and their top 4 most recently updated repositories in a modern, dark-themed interface.

This version was adapted for the **Computer Networks** course: the browser no longer talks to GitHub directly. Instead, a Python server written with raw **sockets** (standard library only, no framework) serves the front end and fetches the data from the GitHub REST API on its behalf.

**Original version (front end only):** [GitHub Explorer](https://github-explorer-eight-tau.vercel.app/)

---

## 🧭 How it works

```text
Browser ──HTTP──▶ server.py ──TLS socket──▶ api.github.com
  (React)        (socket server)           (github_client.py)
                      │
                      └──▶ static.py ──▶ dist/ (Astro build)
```

1. The browser loads the page from the Python server (`/`), which serves the files from `dist/`.
2. The React app calls the server's own API (`/api/users/...`).
3. The server validates the request and asks `github_client.py` for the data.
4. `github_client.py` opens a TCP socket to `api.github.com:443`, wraps it with TLS (`ssl`), writes the HTTP request by hand and parses the response.
5. The server forwards the JSON (or the error status) back to the browser.

Everything is served from the same origin (`http://localhost:8000`), so no CORS setup is needed.

### Where each requirement lives

| Requirement         | File                      |
| :------------------ | :------------------------ |
| Socket server       | `server/server.py`        |
| Socket client + TLS | `server/github_client.py` |
| GitHub REST API     | `server/github_client.py` |
| Static file serving | `server/static.py`        |
| End-to-end tests    | `test_server.py`          |

## 🚀 Key Features

- **Real-time Search:** Fetch user data through the socket server, which queries GitHub's REST API.
- **Loading States:** Skeleton screens providing visual feedback during network requests.
- **Error Handling:** Distinct screens for an unknown user (404), an invalid username (400), the GitHub rate limit (403) and an unreachable server or GitHub (502 / network failure).
- **Input Validation:** Usernames are validated on the server (`A-Z`, `a-z`, `0-9`, `-`, up to 39 characters) before anything is sent to GitHub.
- **Safe Static Serving:** Path traversal attempts such as `/../server/server.py` return 404.
- **Responsive Design:** Fluid layout optimized for both desktop and mobile devices.

## 🔌 API

All responses are the GitHub JSON, forwarded unchanged on success.

| Route                             | Description                          |
| :-------------------------------- | :----------------------------------- |
| `GET /api/users/{username}`       | Public profile of the user           |
| `GET /api/users/{username}/repos` | 4 most recently updated repositories |

| Status | Meaning                               |
| :----- | :------------------------------------ |
| 200    | Success                               |
| 400    | Invalid username or malformed request |
| 403    | GitHub rate limit reached             |
| 404    | User or route not found               |
| 500    | Internal server error                 |
| 502    | GitHub could not be reached           |

Errors generated by the server itself (400, 500, 502) come as `{"message": "..."}`.

## 💻 Running the project

### Prerequisites

- **Node.js** (to build the front end) and **npm**
- **Python 3.8 or newer**. There is nothing to install with `pip`: only the standard library is used.

### Steps

1. **Clone the repository**

```bash
git clone <repository-url>
cd gitexplorer
```

2. **Install dependencies and build the front end**

```bash
npm install
npm run build
```

3. **Start the server**

```bash
python server/server.py
```

4. **Open the app** at [http://localhost:8000](http://localhost:8000).

### Optional: GitHub token

Without a token, GitHub allows 60 requests per hour per IP address. With a personal access token the limit rises to 5000 per hour. Set `GITHUB_TOKEN` before starting the server:

```bash
# Linux / macOS
export GITHUB_TOKEN=your_token_here
python server/server.py
```

```powershell
# Windows (PowerShell)
$env:GITHUB_TOKEN="your_token_here"
python server/server.py
```

The token is only read by the Python server and is never sent to the browser.

### Front-end development mode (optional)

To work on the React code with hot reload, run the server and the Astro dev server side by side, and point the front end at the API:

1. Create a file named `.env.development` in the project root:

```text
PUBLIC_API_URL=http://localhost:8000
```

2. In one terminal run `python server/server.py`, and in another run `npm run dev` (served at `http://localhost:4321`).

Use `.env.development` and not `.env`: Astro also reads `.env` during `npm run build`, which would bake the URL into the build that the Python server delivers.

## 🧪 Tests

With the server running in one terminal, run in another:

```bash
python test_server.py
```

The tests send raw HTTP text over a TCP socket and check the status code of the response:

- existing user → 200
- missing user → 404
- invalid username (`..%2Forgs`) → 400
- unknown API route → 404
- path traversal (`/../server/server.py`) → 404
- home page served as `text/html`
- malformed request → 400

Each test uses a request to GitHub at most once, so running them a few times stays well inside the 60 requests/hour limit.

## 🩹 Troubleshooting

| Problem                                    | Fix                                                                                 |
| :----------------------------------------- | :---------------------------------------------------------------------------------- |
| Every page returns `404 Not Found`         | `dist/` does not exist yet. Run `npm run build`.                                    |
| `Address already in use` on startup        | Another process is using port 8000. Stop it or change `PORT` in `server/server.py`. |
| "Request limit reached" on the page        | GitHub rate limit. Wait, or set `GITHUB_TOKEN`.                                     |
| "The server is currently down" on the page | The Python server is not running, or it cannot reach GitHub.                        |
| Blank page after a search                  | Open the browser console (F12). Usually the API returned an unexpected format.      |
